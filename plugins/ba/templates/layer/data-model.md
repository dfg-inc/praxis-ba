> **Что это за документ.** Единый реестр сущностей данных проекта. Создаётся на фазе Research, пополняется по мере появления новых FS.
>
> **Кто создаёт:** агент генерирует заготовку в начале проекта. На старом проекте — агент делает reverse-engineering из кодовой базы (ORM-модели, схемы БД, миграции) или из API-контрактов (OpenAPI/Swagger).
>
> **Кто пополняет:** на фазе Research ba-research предлагает новые сущности при сборе FS; на фазе Plan ba-plan сверяет `data_model_refs` и предлагает недостающие (секция "Данные" FS). BA утверждает определение и тип операций. Агент добавляет сущность сюда.
>
> **Как использовать в FS:** в секции "Данные" каждого FS — ссылки на якоря сущностей (`#название-сущности`) + тип операции (создание / чтение / обновление).

## Как описывать сущность

> Каждая сущность — отдельный раздел `##`. Название раздела = имя сущности (то, что будет якорем ссылки).
> Поля описываются только на уровне BA — бизнес-смысл, не технические детали реализации.
> Типы полей: string, number, boolean, date, uuid, enum, geojson, reference (ссылка на другую сущность).

```markdown
## [Название сущности]

**Описание:** [что это за объект в бизнес-терминах, 1-2 предложения]
**Источник:** [откуда появляется — создаётся пользователем / приходит из внешней системы / генерируется автоматически]
**Затрагивается в:** [FS-001, FS-003] — заполняет агент по мере появления FS

| Поле | Тип | Описание | Обязательное |
|------|-----|----------|--------------|
| id | uuid | Уникальный идентификатор | да |
| [поле] | [тип] | [бизнес-смысл поля] | да / нет |

**Связи:**
- [Другая сущность] — [тип связи: один к одному / один ко многим / многие ко многим]

**Примечания:** [бизнес-ограничения, особенности которые важно знать — не техника]
```
